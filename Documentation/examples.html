Lib3MFToolpath4EOS examples

Overview

Five command line programs cover the Lib3MFToolpath4EOS workflows, and toolpath_credential stores the Toolpath API client key. Each is a single C++ file in examples/cpp, sharing the helpers in example_common.hpp (argument parsing, library loading, waiting for futures). They use the dynamic C++ bindings and only need lib3mftoolpath4eos.dll and lib3mf.dll next to the executable; in a binary release they are in bin/.

Building

In the repository, the examples are part of the main build and end up in build/Examples/Release:

cmake -S . -B build
cmake --build build --config Release

In a binary release, examples/CMakeLists.txt is a standalone project that uses the release's headers and DLLs:

cmake -S examples -B build-examples
cmake --build build-examples --config Release

In the repository, the standalone project needs the built library: -DLIBEOS_DLL=<path>/lib3mftoolpath4eos.dll.

Common options

Every example prints its usage with --help. Options can also come from environment variables.

OptionEnvironment variableMeaning
--sdk <dir>LIBEOS_SDK_DIREOSPRINT API directory; auto-detected if omitted
--log <file>EOS SDK log file; a temporary file is used if omitted
--material-set <file>LIBEOS_MATERIAL_SETMaterial set (.eospar) to embed if the 3MF has none
--machine-config <path>LIBEOS_MACHINE_CONFIGConfiguration directory or machine package file
--client-id <id>LIBEOS_TPAPI_CLIENT_IDToolpath API client ID
--credential <name>LIBEOS_TPAPI_CREDENTIALName of the Windows Credential Manager entry with the Toolpath API client key (see below)
--machine <address>LIBEOS_MACHINE_ADDRESSMachine network address; without it, the connection is simulated
--store-task <dir>Also copy the created task into this directory

The exit code is 0 on success, 2 for usage errors and 1 for all other errors.

If both EOSPRINT 2 and the EOSPRINT API SDK are installed, auto-detection picks EOSPRINT 2. Select the SDK with --sdk "C:\Program Files\EOS\EOSPRINT 2 SDK\2_18\bin\x64\release".

Walkthrough

Generate a sample part with an embedded material set. The first run lists the exposure sets and stops, because no --part-parameter is given; the second run picks one:

00_generate_sample_3mf.exe box.3mf --material-set 316L_040_FlexM291.eospar
00_generate_sample_3mf.exe box.3mf --material-set 316L_040_FlexM291.eospar --part-parameter _Default_DirectPart

Convert to OpenJZ and back:

01_convert_3mf_openjz.exe box.3mf box.openjz
01_convert_3mf_openjz.exe box.openjz box_roundtrip.3mf

Create tasks and upload them. Without --machine the connection is simulated, which requires an explicit machine configuration:

02_openjz_to_machine.exe --machine-config M290.eosmachineinformation --store-task tasks box.openjz
03_mesh3mf_to_machine.exe --machine-config M290.eosmachineinformation --machine 192.168.0.10 box.3mf

To expose your own toolpaths, write them into a 3MF with the 3MF Toolpath extension, using the profile parameters of the 3MF conventions. Store the Toolpath API client key once and create a task from the toolpath 3MF:

toolpath_credential.exe store LibEOS-TPAPI client_key.pem
06_toolpath3mf_to_machine.exe --machine-config M290.eosmachineinformation --client-id 1 --credential LibEOS-TPAPI my.toolpath.3mf

EOS Toolpath API

Example 06 uses the EOS Toolpath API, which requires an agreement with EOS GmbH and authorization by EOS. EOS process data, including EOS toolpaths and 3MF files containing EOS process data, must not be made accessible to third parties in human- or machine-readable form. See EOS Toolpath API in the library documentation.

Toolpath API client key

The client key (the client-side encryption key that EOS assigns under the Toolpath API agreement) is a PEM file and a confidential credential, even though RSA libraries may refer to it as a "public key". The examples do not read it from a file: toolpath_credential stores its PEM text once as a generic credential in the Windows Credential Manager, which encrypts it for the current Windows user, and the examples get the credential's name with --credential:

toolpath_credential.exe store LibEOS-TPAPI client_key.pem   # import the file issued by EOS
toolpath_credential.exe store LibEOS-TPAPI                  # or paste the PEM text into the console
toolpath_credential.exe check LibEOS-TPAPI                  # shows the PEM type and size, never the key
toolpath_credential.exe delete LibEOS-TPAPI

After importing, remove the PEM file from the computer and keep the original in a secure place. The credential is bound to the Windows user that stored it; a service under another account needs its own entry. The examples pass only the credential name to AuthenticateToolpathAPIFromCredentialStore; the library reads the key and erases its copies after authenticating, so the key never passes through the example.

00 Generate sample 3MF

00_generate_sample_3mf [options] <output.3mf>

Writes three parts that exercise part placement: a 20 mm cube moved by its build item, a 40 × 10 × 10 mm bar rotated by 30° about Z, and a 10 mm cube placed through a components object.

With --material-set, the material set is imported (this loads the EOS SDK), its exposure sets are listed and it is embedded. --part-parameter must then name one of the listed exposure sets and is stored as eos3mf:partparameter on every part.

API: ImportMaterialSet, EOSMaterialSet::GetExposureSetName, AttachMaterialSetTo3MF.

01 Convert 3MF / OpenJZ

01_convert_3mf_openjz [options] <input.3mf|input.openjz> <output>

The direction follows the input extension. For 3MF input, the material set comes from the file or from --material-set. For OpenJZ input, the geometry, part metadata and the OpenJZ's material set are written into a mesh 3MF.

API: Convert3MFToOpenJZ, ConvertOpenJZTo3MF.

02 OpenJZ to machine

02_openjz_to_machine [options] <job.openjz>

Loads the job, activates the machine configuration, creates an EOS task and uploads it. The machine configuration is --machine-config if given, otherwise it is downloaded from the connected machine.

API: ConnectToMachine, LoadOpenJZFromFile, ActivateMachineConfiguration, CreateTask, UploadTask.

03 Mesh 3MF to machine

03_mesh3mf_to_machine [options] <model.3mf>

Like example 02, but the job comes from a mesh 3MF with an embedded material set.

API: LoadJobFrom3MF, ActivateMachineConfiguration, CreateTask, UploadTask.

06 Toolpath 3MF to machine

06_toolpath3mf_to_machine [options] <toolpath.3mf>

Reads a toolpath 3MF from your own toolpath generation through a persistent source, writes its layers into an EOS task and uploads it. Besides the toolpath, the 3MF needs the part meshes and an embedded material set, or else all eos3mf job metadata.

After the task is created, or if creating it fails, the example prints the conversion log: the message counts, the warnings and errors, and the counters that are not 0. --conversion-log <file.json> also writes the log as JSON, and --power-ramp-mode selects polyline (default), split-hatches, flatten or reject.

API: CreateToolpathConversionSettings, CreateTaskFrom3MFToolpath, GetConversionLog, UploadTask.

Notes for your own code

  • Load lib3mf.dll and lib3mftoolpath4eos.dll and call InjectComponent("Lib3MF", ...), so both libraries share one Lib3MF instance (loadLibraries).
  • Register the material set relationship with AddRelationToRead before reading a 3MF, otherwise Lib3MF drops the attachment (read3MF).
  • Read toolpath 3MFs with ReadFromPersistentSource and keep the source alive (read3MF).
  • Call EnableSDKSimulation before anything loads the SDK (createContext).
