Conversion settings and log

Summary

Every conversion of a toolpath into an EOS task takes an EOSToolpathConversionSettings object and produces an EOSConversionLog. This applies to CreateTaskFrom3MFToolpath and to raw task writers from CreateRawTaskWriter.

auto pSettings = pContext->CreateToolpathConversionSettings();   // defaults
pSettings->SetPowerRampMode(Lib3MF4EOS::eEOSPowerRampMode::SplitHatches);

auto pTask = pContext->CreateTaskFrom3MFToolpath(pModel, pConfig, pSettings, "part", "", "MyApp", "1.0");
// wait for the future, also if it failed ...
auto pLog = pTask->GetConversionLog();
std::cout << pLog->GetCountBySeverity(Lib3MF4EOS::eEOSLogSeverity::Warning) << " warnings" << std::endl;
std::ofstream("conversion.json") << pLog->ToJSON();

A conversion copies the settings when it starts. Changing the settings object afterwards does not affect it, and one object can be used for several conversions.

Settings

Each setting has a Set and a Get method, for example SetMaxPowerStep and GetMaxPowerStep. A setter fails with INVALIDCONVERSIONSETTINGS if the value is out of range, and the object keeps its previous value. ResetToDefaults restores all defaults and ToJSON returns the settings in the form they take in the conversion log.

Exposure sets per thickness

A material set can have no or several exposure sets for a layer thickness. In that case the exposure set can be assigned per thickness, separately for parts and supports:

pSettings->SetExposureSetForThickness(60, false, "Part_60um");     // parts at 60 µm
pSettings->SetExposureSetForThickness(60, true, "Support_60um");   // supports at 60 µm
pSettings->SetExposureSetForThickness(60, true, "");               // removes the support assignment
std::string sName = pSettings->GetExposureSetForThickness(60, false);
pSettings->ClearExposureSetsForThickness();

The thickness must be positive.

CreateTaskFrom3MFToolpath chooses the exposure set of each part without eos3mf:partparameter in this order:

  1. the assignment for the part's layer thickness and support flag;
  2. the only exposure set of the material set with that thickness and support flag;
  3. _Default_DirectPart or _Default_ExternalSupport, if AllowDefaultExposureSets is on.

Otherwise the conversion fails with EXPOSURESETAMBIGUOUS. The layer thickness of a part is derived from its toolpath layers, see layer Z and thickness. If that is not possible, the job's materialthickness (from the eos3mf metadata or the material set) is used.

If a profile has no exposed depth of its own, the part's layer thickness is written as the exposed depth.

Layer Z and thickness

A 3MF toolpath gives one Z value per layer. EOS gives the Z of the top of a layer, measured from the build plate. LayerZConvention tells how the toolpath Z values are read:

ConventionEOS layer ZNotes
TopThe toolpath Z.A first layer at Z 0 fails with LAYERZINVALID, since a layer cannot end at the build plate.
BaseThe toolpath Z plus the layer thickness.All parts need the same layer thickness, otherwise the conversion fails with LAYERZINVALID.

The Z values must increase from layer to layer, otherwise the conversion fails with LAYERZINVALID. If the first layer is at a Z equal to the layer distance, both conventions are plausible. The conversion goes on with the chosen one and logs LAYER_Z_AMBIGUOUS.

The layer thickness of a part is the smallest distance between the layers in which it has vectors. A part may skip layers, for example a part at 60 µm in a job with layers every 30 µm, but every distance between its layers must be a multiple of its thickness, with a tolerance of 1 µm per layer. Otherwise the conversion fails with LAYERTHICKNESSINCONSISTENT. A part with fewer than two layers gets the smallest layer distance of the toolpath, and a toolpath with fewer than two layers gets the job's materialthickness. A part thickness that is not a multiple of the job's material thickness is logged as PART_THICKNESS_NOT_MULTIPLE.

The machine target of the job is taken, in this order, from eos3mf:machinetarget, from the model type of the machine configuration, and from the material set. If none is known, the conversion fails with UNKNOWNMODELTYPE. A material set made for another machine is logged as MACHINETARGET_MISMATCH.

Pre-flight checks

After the job is loaded, CreateTaskFrom3MFToolpath asks the EOS SDK for the layer stack of the job and its process heights, and compares them with the toolpath:

  • A toolpath layer without a layer of the stack at its Z is LAYER_NOT_IN_STACK. With strict mode on, the conversion fails with LAYERSTACKMISMATCH; otherwise it is a warning.
  • Layers in which the toolpath exposes a part but the job does not, and the other way round, are logged per part as warnings.
  • If the job needs more Z travel than the machine allows, the conversion fails with PROCESSHEIGHTEXCEEDED.
  • A Z shrinkage compensation of the job (accumulatedShrinkageCompensation) cannot be applied to a toolpath. With strict mode on, the conversion fails with SHRINKAGECOMPENSATIONNOTSUPPORTED; otherwise it is a warning and the toolpath is written at its own Z.

When all toolpath layers are on the stack, every exposed stack layer without toolpath is filled while the layers are written: every scanner begins one of the layer's parts and nothing is exposed (LAYER_FILLED, counter layersFilled).

An EOS SDK that does not give the layer stack is logged as LAYER_STACK_UNAVAILABLE and the check is left out.

Two methods of EOSContext run checks without creating a task. Both return an EOSConversionLog and fail only for invalid arguments.

// The checks of CreateTaskFrom3MFToolpath, without writing layers. Failures are CHECK_FAILED errors in the log.
auto pCoverage = pContext->CheckLayerCoverage(pModel, pConfig, pSettings);

// Compares the bounds of each part's mesh with the bounds of its vectors, with a tolerance in mm.
auto pAlignment = pContext->CheckPartToolpathAlignment(pModel, 0.2);
std::cout << pAlignment->GetSummaryValue("partsMisaligned") << " parts misaligned" << std::endl;

CheckPartToolpathAlignment needs neither the EOS SDK nor a machine. A part is misaligned if the XY bounds of its vectors differ from those of its mesh by more than the tolerance, or if its layers lie below its mesh or more than one layer distance above it. The message then gives the differences and, if the vectors look shifted, the shift in X and Y.

Conversion log

The log is available from TaskCreationFuture::GetConversionLog and from EOSRawTaskWriter::GetConversionLog. A future and its writer share the same log, so it keeps growing while the SDK creates the task. Each call returns a new handle on the same data.

MethodReturns
GetLogMessageCount, GetLogMessageThe messages in the order they were added: severity, code, layer index, part ID and text.
GetCountBySeverity, HasErrorsNumber of messages per severity, and whether there is an error.
GetSummaryValue, GetSummaryValueCount, GetSummaryValueByIndexThe counters. An unknown counter is 0.
ToJSONThe whole log, see JSON format.

A message that repeats for many vectors, for example a flattened ramp, is stored once per code, layer, part and text, and counts its repetitions. Its text ends with the number of repetitions, for example "(12 times)".

The layer index is the 0-based 3MF layer index for CreateTaskFrom3MFToolpath, and the index passed to WriteLayer for a raw task writer. It is -1 if a message is not about a layer, and the part ID is 0 if it is not about a part.

The methods are called GetLogMessageCount and GetLogMessage, because windows.h defines GetMessage as a macro.

Failed conversions

CreateTaskFrom3MFToolpath fails right away only for invalid arguments: a null model or machine configuration, invalid settings, or a model without a toolpath. If the conversion itself fails, for example on a rejected power ramp or unsupported toolpath data, it returns a future that has already failed. HasFailed is true, GetErrorMessage describes the problem and the log ends with a CONVERSION_FAILED error. The log still holds everything collected up to the failure, including the profiles read so far. This also applies to failed layer checks (LAYERZINVALID, LAYERTHICKNESSINCONSISTENT) and pre-flight checks (LAYERSTACKMISMATCH, PROCESSHEIGHTEXCEEDED, SHRINKAGECOMPENSATIONNOTSUPPORTED).

If the SDK fails later while creating the task, the future fails as before and the log gets a TASK_CREATION_FAILED error.

WriteLayer of a raw task writer still throws. Its log is available from the writer.

JSON format

EOSConversionLog::ToJSON returns one UTF-8 JSON object. Keys are camelCase, enumerations are written with their API names, lengths are in mm and powers in W. Unknown values are null. New keys can be added in later versions without changing formatVersion; readers should ignore keys they do not know.

KeyContent
formatVersion1.
hasErrorsWhether there is an error message.
libeosversion of Lib3MFToolpath4EOS.
sdkdirectory, productVersion (null if unknown), versionSource (productVersionFunction, dllVersionResource or notDetected), adapterVersion (the declarations used), openJobVersion, fullSimulation and versionMessages. Null if the conversion failed before the SDK was loaded.
settingsThe settings of the conversion, as returned by EOSToolpathConversionSettings::ToJSON.
unitsmodelUnitInMM, toolpathUnitInMM, layerZConvention, layerZSource (where the layer Z comes from), layerDistance (the smallest layer distance, in µm) and eosZOffset (added to the toolpath Z, in µm). Only CreateTaskFrom3MFToolpath and CheckLayerCoverage.
partsArray of the parts of the model: partId, name, buildItemUUID, isSupport, partParameter, exposureSet (null until chosen), toolpathLayers, layerThickness (in µm), layerThicknessSource (partLayers or toolpathStep), firstLayerZ and lastLayerZ (EOS Z, null for a part without layers). Only CreateTaskFrom3MFToolpath and CheckLayerCoverage.
layerStacksimulated (true in full SDK simulation), layers, firstLayerZ, lastLayerZ and processHeights (preProcessHeight, bottomOffsetHeight, payloadHeight, topOffsetHeight, postProcessHeight, accumulatedShrinkageCompensation, totalZTravel, maxZTravel). Only if the layer stack was checked.
alignmentArray per part: partId, name, mesh (bounds), toolpath (XY bounds, firstLayerZ, lastLayerZ) and maxDeviation. Only CheckPartToolpathAlignment.
profilesArray of the toolpath profiles used: uuid, name, laserIndex, laserPower, scanSpeed, focus (the eos:focus value, null if the profile has none), laserFocusOffset (the laserfocus offset in mm), exposureType (null if the profile has none), skywriting, exposureSetIndex, exposureStepIndex, pulsedWavePeriodTime, pulsedWavePowerOnTime, exposedDepth, preDelay, postDelay, preWaitTime (prewaittime in the dwell time unit), dwellTime (postwaittime in the dwell time unit), beamShapeProfile (null if none), powerModifier, speedModifier, focusModifier and dwellModifier (each null or type, factor, minValue, maxValue), constantModifiers, unsupportedModifiers and unsupportedParameters (name, with the namespace in front if it has one, and reason). Only CreateTaskFrom3MFToolpath.
lasersArray of the laser indices that are declared or used: laserIndex, scannerIndex (the scanner written to the task; null for an undeclared index), declared and used. Only CreateTaskFrom3MFToolpath.
scannersArray of the scanners written to: scannerIndex, exposedLayers (layers with blocks on the scanner), idleLayers (layers in which it only got a part begun), blocks, preDelays and preDelayMicroseconds (their sum).
summaryObject with the counters.
messageCountsinfo, warning and error.
messagesArray of messages: severity (info, warning or error), code, layerIndex and partId (null if not about a layer or part), text and count (number of repetitions).
